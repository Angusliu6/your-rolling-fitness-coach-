# 交互格式模板

## A. 进入健身房

```
今日方案：腿 + 背（原因：上次胸肩刺激足够；今天背/腿恢复允许）
可用 45 分钟 | 目标 11–13工作组 | RIR 1–2
| 顺序 | 动作 | 组×次 | 休息 |
| 1 | 腿举 | 3×8–12 | 120秒 |
| 2 | 高位下拉 | 3×8–12 | 90秒 |
| 3 | 胸托划船 | 3×8–12 | 120秒 |
| 4 | 腿弯举 | 2×10–15 | 75秒 |
优先做1–3；到时间可结束。以下为每个动作1个动作要点和可靠演示入口。
```

## B. 训练现场改计划

```
已完成：推胸4工作组，推肩2工作组，侧平举2工作组；侧平举动作变形。
判定：胸肩累计刺激明显，今天不继续加肩。剩余20分钟补腿举2组 + 腿弯举2组；人多时高脚杯蹲替代腿举。
待确认：侧平举10kg是每只还是总重？若只剩几分钟可直接结束。
```

## C. 训练后总结

```
SESSION #N 已完成：...
实际工作组：X；体感疲劳：Y/10（未报则未知）
本次有意义进步：只有可比数据时填写
因器械占用未完成：...（不记为0组，也不强制补课）
下次候选：腿+背；下次当天再按恢复调整。
```

## D. 饮食汇报

```
已吃：燕麦（量未知）、香蕉1根；待确认：乳清1份；已点未喝：美式。
估算：目前食物克数不足，无法准确给出总热量；若乳清提供约20–25g蛋白，能帮助训练日补足蛋白。
下一顿：正常主食+优质蛋白+蔬菜。
关键问题：燕麦大约几克？
```

## E. 训练与饮食周复盘

```
本周已报告训练：2次，按实际组累计肩X组、胸Y组、背Z组、腿W组。
负重/次数趋势：...（若无法比较，明确指出）
已报告蛋白：N天，全天数据完整度...（不把漏报当作缺口）
调整：先修复恢复/饮食问题；若目标肌群连续多次暴露停滞再小幅增组。
下次候选：...
```

## 用户输入最简自然语言

- “到了，今天40分钟，肩还酸，腿比较想练。”
- “侧平举5kg：16/14/12，后两组耸肩明显。”
- “今天练完了，机器太挤，只做了上面3个动作。”
- “刚才吃了半碗饭，鱼一份，具体没称重。”
- “今早体重63.2，今天饮食结算。”

不要要求用户规范填写表单；从自然语言提取，必要时只问最关键的一个缺口。


## F. Interactive UI / 逐组训练记录（v1.2）

训练前：展示可空的当日体重（kg/斤）与称重条件、训练时间和恢复；**先于**正式组列表。进入训练后，按动作逐组呈现实际重量（每只哑铃或器械）、实际次数、RIR 与“已完成”勾选，且各组重量独立。默认所有组未完成；未填写的数字不等于零。

```text
练前：体重[空]kg / 斤；条件[晨空腹 / 饭后训练前 / 未知]；时间[60]分钟
上斜推胸
  组1 [完成?] [重量__kg] [次数__] [RIR__]
  组2 [完成?] [重量__kg] [次数__] [RIR__]
器械换了？ [更换动作] 组数不够？ [加组 / 减组]
腹肌 反向卷腹：2×10–15（正常情况下纳入总时长）
训练结束 → 仅复制/导出真正已完成的组
```

参见 [交互规格](interactive-ui.md) 和 [可打开的本地演示页](../docs/training-ui.html)。若宿主不支持互动 UI，提供自然语言反馈格式，不宣称宿主自动运行 HTML。
