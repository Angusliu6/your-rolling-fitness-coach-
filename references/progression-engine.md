# 逐组渐进超负荷引擎 / Per-set Progressive Overload

## 产品目标

每次训练不是固定重复同一份表格：依据**同一动作/同一器械/相同负重口径**的历史正式组，生成下一次**每组目标重量、目标次数、RIR、组间休息与动作节奏**。当前 AI Skill 负责对话解释与现场调整；确定性计算可交给 `scripts/progression_db.py`；**未提供持久文件/数据库权限的 ChatGPT 对话不能自行保证保存历史**。

## 数据优先规则

- 只把用户明确做过的工作组入 `actual_sets`；热身、计划、未完成不算工作组。
- 每个动作统一规范名，但保留原始说法；遇到“宽内展”这类含糊名称，先保留未归一化文本，不能擅自映射成“髋内收”、“上斜胸推”等。
- 每组记录：`load`、`unit`、`load_basis`（每只哑铃/杠铃总重/器械配重）、`equipment`（具体机器/阻力档位/把手条件）、`reps`、`rir`、`failure`、`form`、`rest_seconds`、`eccentric_seconds`、`concentric_seconds`。
- 无法确认的记录保留 `null`，不能从前一次或示例数据填充；**每组都是独立观测**。
- 训练计划与真实日志分表；用户确认才保存“已完成”。逐组记录可分批提交以抵御训练中断。

## 建议算法：先次数后重量（双重渐进）

以 3 组×8–12 次的器械胸推为例：

| 上次：25kg，规范工作组 | 下次建议 | 状态 |
| --- | --- | --- |
| 12/11/9 次，约 RIR 1–2 | **25kg × 12/12/10（目标）** | 保持重量，先提升完成次数 |
| 12/12/12，全部动作规范，RIR≥1 | 升到器械可用的下一档，如 **27.5kg × 8/8/8** | 进入下一负重档，再爬次数 |
| 第3组不足8次且真实力竭 | 休息更充分、或下降一档重量 | 先保证动作质量，不强追记录 |
| 只说“25kg、三组到力竭”而**没有次数** | 暂时不加重；请补每组次数、是否最后一组真正力竭 | 数据不足 |
| 肩前方疼痛/明显急性不适 | 停止相关推举，先排除问题 | 安全优先 |

这是一套**保守的默认规则**，不是临床处方，不保证每次训练都需要加重。相同重量如果增加规范次数、改善幅度/控制、降低余力，仍可能有效；同重同次数也不能仅凭一次就判定“毫无增肌效果”。停滞需结合多次训练、恢复和饮食判断。

## 个人记录 Personal Records

- `PR` = 个人最好训练成绩（Personal Record），按**同一动作+器械+单位+负重口径**独立比较。
- `Load PR`：该可比条件下技术合格的最高负重（需联看完成次数）。
- `Rep PR`：同一重量下最多规范次数。
- `e1RM`：只有技术合格、接近极限（RIR≤1）、重复数1–10等数据齐全时，才可用 Epley `load * (1 + reps / 30)` 给出**粗略估计**；永远不要把器械 e1RM 当作真实测试的卧推1RM，也不宜跨机器比较。
- 如果用户说“BP”，问清是在指 `PR`（个人纪录）还是 Bench Press（卧推），不要自行扩写成某个身体数据。

## 每组节奏与休息建议

- 稳定增肌动作：下放（离心）约 **2–3秒**、推/拉起约 **1–2秒**，不刻意拖慢到极端；自然呼吸，不屏气过久。比如10次可持续约30–50秒，但**不是必须达到一个精确的秒数**。
- 大复合动作常见 **2–3分钟**休息；中小肌群孤立动作 **60–120秒**，按动作质量、心率和训练表现个体化；达不到目标次数时可合理延长。
- 组间主要让呼吸平稳、补水、适当走动或轻度活动；不要求每组做强力静态拉伸，避免疲劳的目标肌群在组间被强拉。若拉伸可做轻柔无痛动作，正式静态拉伸可放到训练后或另一个时段。
- 疼痛、病史或功能受限时先评估，不用“冲PR”作激励。

## 训练现场协议

1. 开练时读取最近同动作的可比日志、疲劳和器械可用性。
2. 输出表格：第1、2、3组各自的重量 / 目标次数 / RIR / 休息 / 节奏；标明只是**目标**而不是完成记录。
3. 用户报告第1组后，可按实际表现与剩余时间重算剩余组（特别是超出预期疲劳时）。
4. 完成后展示历史对照：最高规范重量、各组次数、是否达到加重条件、下次建议。
5. 不清楚机器名称、单位、是每只哑铃还是总重量时，**暂停数字比较和加重**，只给保守操作建议。

## 工程边界

当前 `scripts/progression_db.py` 已实现单机离线 SQLite 日志、同器械的双重渐进初步建议、PR/e1RM（谨慎估算）。不是手机端云后端，不会从 ChatGPT 对话自动写进用户手机上的数据库。见 `docs/DATA_STORAGE.md`。若未来上云，必须有认证、授权、传输加密、数据导出/删除和备份策略；GitHub 只托管源码，绝不上传个人训练数据库。
